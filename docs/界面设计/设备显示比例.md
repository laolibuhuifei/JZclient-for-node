# 不同设备的默认显示比例

手机保持 100%，其他设备统一使用 90%。规则覆盖桌面、笔记本、安卓平板和 iPad，也作用于账号验证界面、页面弹窗和浮层。

显示比例根据浏览器的手机标识判断，不根据当前窗口宽度判断。因此桌面窄窗口仍为 90%，手机横屏仍为 100%。识别包含 Android Mobile、iPhone、HarmonyOS Phone 等手机标识和浏览器提供的 `userAgentData.mobile`；iPad、Tablet 等平板标识归入 90%，iPad 的桌面浏览器标识也归入 90%。

## 实现方式

页面在打开时加载 [display-scale.js](../../src/assets/display-scale.js)，在根元素设置 CSS `zoom` 和 `--ui-scale`。字体继续使用 `JZCatBook`，现有 MD3 颜色和组件继续沿用。

地图瓦片、标记与半径保持同一套布局坐标。鼠标和触摸的屏幕坐标按显示比例换算，地图选点、拖动、滚轮缩放不会因 90% 显示而偏移。设备浮层、MD3 下拉菜单、半径说明及导航选中动画使用同样的换算；固定弹窗和全屏聊天的可用高度同步适配。

页面脚本由后端按 JavaScript 类型提供并使用 `no-cache`，开发预览和正式 WebUI 使用同一份规则。

## 验证范围

2026-11-16，前端正式回归 62/62。新增设备识别检查覆盖手机、安卓平板、iPad 移动与桌面标识、桌面窄窗口、HarmonyOS 手机和浏览器手机标记；新增实际地图组件检查覆盖 90% 下选点、拖动、滚轮的坐标及不误触发保存。

真实 `8787` 页面在 Edge 中确认根元素 `zoom=0.9`，实际查看了区域编辑与半径说明弹窗。默认桌面视口为 1912×970；820×1180 下导航指示层与按钮完全对齐；390×844 下更多菜单保留在底部导航上方且无横向溢出。窄窗口全屏聊天宽390、高约843.3，输入区在844高的可视视口内。检查只读或改变本地界面状态，没有发送消息或保存区域，结束后恢复默认视口。

手机100%的判断由实际初始化脚本的自动检查确认，本次未使用实体手机或平板。更改浏览器的设备标识后，重新加载页面会重新判断比例。

源码见 [displayScale.ts](../../frontend/src/lib/displayScale.ts)、[material-theme.css](../../frontend/src/material-theme.css) 及各地图、浮层和导航组件。
