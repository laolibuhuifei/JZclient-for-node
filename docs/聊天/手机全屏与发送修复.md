# 手机全屏聊天与发送修复

手机点击会话后进入铺满可视视口的聊天页面。全局顶栏、底部导航、页面标题、设备选择和页脚暂时隐藏，屏幕只保留会话标题、消息和输入区。返回按钮回到原会话列表，桌面继续使用左侧列表与右侧聊天的布局。

## 页面设计与交互

聊天沿用原 `JZCatBook` 字体和全站 MD3 深浅色主题。返回按钮与头像在左，孩子名称在右；手机将紧凑的 IM 状态放在名称下方。会话头像继续按对应设备资料读取，不受全局所选另一台手表影响。

消息区独立滚动，输入区贴在可视视口底部并为系统安全区域留白。手机会话是普通页面中的 `section`，没有聊天 Dialog；表情、录音、位置等发送工具仍可使用原弹窗。

页面通过 `visualViewport` 高度及顶部偏移适应可视空间变化，并在会话期间锁定文档滚动；返回、离开页面或卸载时恢复。窗口变为桌面宽度后恢复普通外壳和两列布局。各会话保留未发送草稿，返回后再进入也保留，Enter 与输入法规则继续使用原逻辑。

## 群聊超时怎么修复

会话目标使用字符串保存 ID，而 IM 的 TLV 编码根据 JavaScript 类型决定字节格式。原群发送把字符串群 ID 直接送入数字字段，编码成为 UTF-8 文本，导致发送等不到正常回执。

发送时将 `dialogId` 和 `imAccountId` 转为数字后再写入协议字段，并明确携带 `NEED_RESPONSE=0` 请求发送回执。原消息 JSON、语音包装、消息 ID 和会话选择流程继续保留。单聊接收 ID 也在编码处规范为数字，但没有新增或修复平台会话关系。

经用户授权，2026-11-16 完成一次带测试标记的真实家庭群文本发送：HTTP 200，平台接受回执，约 87ms，无发送超时，本地记录已确认消息。结果见 （历史记录：仅含状态的真实群发送记录）。这说明平台接受发送，不作为手表实际展示或孩子已读的证明。

用户随后确认私聊问题来自手表并要求停止，私聊不再继续测试，也没有自动建立或修改会话关系。

## 实际检查范围

真实 `8787` 页面已用浏览器视口检查以下结果。布局检查仅进入会话、读取数据和填写随后清空的本地草稿，没有发送消息。

| 视口 | 结果 |
| --- | --- |
| 390 × 844 | 主内容与会话均为 390 × 844，消息与输入区在屏内；来自手机全屏实现的前一次检查 |
| 320 × 568 | 主内容与会话均为 320 × 568；头像、返回、工具与输入可见，无横向溢出和可见聊天 Dialog |
| 390 × 420 | 主内容与会话均为 390 × 420；返回按钮为 44 × 44，输入区在视口内，无横向溢出和可见聊天 Dialog |
| 1440 × 900 | 恢复左侧列表、右侧会话及全局导航，无横向溢出 |
| 返回后再进入 | 未发送草稿保留，检查完成后清空 |

320px、短屏及桌面检查加载了包含登录提示的 891,821 字节构建；最后仅调整共享状态对普通读取错误的处理，未修改布局。它们是浏览器视口检查，没有替代实体手机、软键盘或手表端验收；检查结束已恢复默认浏览器视口。个人账号截图仅用于当次查看，不写入公开文档。

本批正式前端、相关后端、类型与构建结果见 [全站 MD3 重构说明的最新记录](../../docs/界面设计/全站MD3重构说明.md)。此前 29 项地图/控件和 12 项插件标签浏览器记录继续保留各自来源，不合并为本批手机检查数。

家长登录失效处理见 [登录失效与重新登录](../../docs/登录与导航/登录失效与重新登录.md)，评论长图字体修复见 [字体兼容](../../docs/评论长图/字体兼容.md)。
