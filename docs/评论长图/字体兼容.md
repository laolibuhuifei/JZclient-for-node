# 评论长图的 Windows 字体兼容

`GET /api/bili/comment/preview` 在这台 Windows 机器上原来报找不到中文 TrueType 字体。字体搜索只包含已有 Linux/macOS 路径，没有覆盖 Windows 的系统字体目录。

字体加载现在根据 `WINDIR` 或 `SystemRoot` 查找系统的 `Fonts` 目录，未配置时使用 `C:/Windows/Fonts`。中文依次尝试微软雅黑 `msyh.ttc`、黑体 `simhei.ttf`、宋体 `simsun.ttc`；英文字母和数字补充尝试 `arial.ttf`、`segoeui.ttf`。原 Linux/macOS 候选和 `JZ_COMMENT_FONT` 显式路径继续使用。

解析器支持带 TrueType `glyf` 轮廓的 `.ttf` 和 `.ttc` 子字体。字体加载仍检查中文字形，CFF/OTF 轮廓不会因扩展名相似而被当作可用字体。部署机器没有这些系统字体时，可用 `JZ_COMMENT_FONT` 指定兼容的文件路径。

这项修改作用于服务端评论图片生成，WebUI 的 `JZCatBook` 字体保持原样。

2026-11-16 验证本机微软雅黑覆盖中文、A 和数字，并实际读取中文字形轮廓。重启后请求公开视频 `BV1GJ411x7h7` 的评论预览返回 HTTP 200、`image/png`，生成 720 × 1500、235,948 字节图片，包含三条评论；实际查看确认中文、英文及数字均正常。
