# 家长登录失效与重新登录

家长账号的登录被平台拒绝时，WebUI 显示「家长账号登录已失效，请重新登录。」和「重新登录」按钮。点击后进入家长账号页，显示原登录表单；登录成功后重新读取手表和相关页面数据，提示随有效登录恢复而消失。

## 怎么识别失效

后端业务 API 客户端识别平台明确返回的 token 无效、过期或未登录说明。在没有表单参数的会话读取 `/dialogaccount/merge/accounts`、`/mobileinit/authid` 中，平台的 `000003 request parameter is invalid.` 也作为会话失效处理。其他接口的普通参数错误、网络失败和 RSA 公钥轮换不触发此提示。

失效记录只对应被拒绝的那张登录票据，并保存在进程内存中。旧请求晚于新登录返回时，不能把新票据标记为失效；重新登录产生有效新票据后即可恢复。原配置中的账号和票据不被自动删除。

| 入口 | 行为 |
| --- | --- |
| 业务接口遇到失效 | 响应带 `parentSessionExpired`，前端发出统一失效事件 |
| `GET /api/account?check=1` | 对尚未确认失效的登录执行只读会话检查，返回 `loggedIn` 和 `sessionExpired` |
| `GET /api/system` | 账号快照包含已知的 `sessionExpired` |
| 页面刷新 | 先检查账号，再读取设备 |
| 页面可见期间 | 每 30 秒检查一次；回到窗口或页面重新可见时也检查 |

已确认失效的票据不再被会话检查反复提交。网络暂时不可用只显示读取失败或保留已有数据，不据此要求重新登录。

## 界面怎么恢复

失效事件由共享 AppContext 处理：显示全局提示，清除已展示的设备列表与当前设备选择，停止依赖有效登录的设备和聊天读取。账号页立即展示重新登录说明和原登录流程，包括原有的多轮验证。

在另一个标签页退出或重新登录后，本页的只读检查也会发现账号状态变化并刷新。主动退出进入普通未登录状态；平台拒绝已有登录则展示上述失效提示。

家长登录和面板访问令牌分别处理。家长登录失效进入账号页；面板 HTTP 401 仍使用原来的访问令牌验证界面。

## 验证

2026-11-16，后端会话测试覆盖失效、新票据恢复、普通参数错误、网络异常、RSA 重试和旧响应迟到隔离。前端使用实际共享 Provider 验证设备清除、恢复以及普通读取错误保留设备；这些自动检查使用离线测试数据。

重启 `8787` 后，对用户已重新登录的账号执行只读检查：HTTP 200，`loggedIn=true`、`sessionExpired=false`。没有为验证提示而退出真实账号或使其失效。整批检查及构建来源见 [全站 MD3 重构说明](../../docs/界面设计/全站MD3重构说明.md)。
