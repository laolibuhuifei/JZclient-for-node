# 危险区域截图与提交修复

原危险区域新增请求把 `areaPic` 固定设为空字符串，平台因此返回 `[000007] 区域截图不能为空`。补上截图后，用户的真实保存又返回 `[000007] 区域详情点不能小于3`：原 `areaDetail` 只有一个中心点和半径，不能满足平台的多边形要求。现在后端生成真实地图截图，并把圆形范围转换成 24 个边界点提交。

平台后续返回 `[000007] 区域详情点不能大于30`，确认边界数量必须为 **3～30 个**。上一版使用了 32 个点，现已调整为 24 个，并在提交前检查数量上下限。回归同时验证多种中心、半径和实际 API 请求的点数符合此约束。

## 保存流程

1. 界面继续提交选定中心的经纬度和半径。
2. 后端先校验坐标及半径；无效数据不请求地图或手表接口。
3. 使用与界面相同的高德普通地图瓦片，在 512×320 的图片中绘制区域范围和中心标记。缩放级别随半径调整，截图始终以提交的中心为准。
4. 以所选中心和半径计算圆周上 24 个等间隔边界点，按从北侧开始、顺时针的顺序组成 `areaDetail`。各点采用原接口坐标约定 `x=latitude`、`y=longitude`，不再提交单点的 `r` 字段，也不重复中心或首点凑数量。
5. 将 PNG 编码为 Base64，随原 `watchId`、`mapType:0` 和多点 `areaDetail` 提交到 `/allDayGuard/addDangerArea`。
6. 成功后刷新区域列表。生成截图或保存失败时，弹窗保留地点、半径和错误说明，方便重试。

边界使用球面距离计算，地球半径取 6,378,137 米，与地图截图的尺度一致；经度自然落在 −180 至 180，日期变更线与极点附近也能生成有效边界。24 边形与界面圆圈之间的最大内缩约为半径的 0.86%。输入无效或不能形成至少三个独立点时，阻止平台提交。

地图请求只使用固定的高德瓦片服务，每次最多并行加载三张。加载失败或收到无效图片时不提交区域，也不生成空白替代图。截图复用项目现有 PNG、Canvas 和图片解码逻辑，不增加新的原生依赖；非 PNG 瓦片沿用现有 ffmpeg 解码。

浏览器保存等待时间调整为 60 秒，保存期间原有控件禁用及关闭保护继续生效。地点名称和地址仍只用于界面，不新增到原区域业务字段。

## 验证

2026-11-16，边界修复后的后端相关回归 36/36。检查覆盖独立边界点、每个点与中心的距离、顺时针排列、赤道、南北半球、日期变更线和极点，以及无效参数不提交；同时验证真实 API 客户端发送非空图片和 24 点边界到原定位服务，并在请求校验中检查 3～30 点限制。截图检查覆盖 PNG 格式、地图与圆形范围、瓦片坐标和图片失败阻止提交。

前端沿用同批已通过的 62/62、类型检查和 871.6KiB 构建；本次边界修复只改变后端提交数据，没有改动前端布局。

对公开的上海人民广场坐标实际加载地图瓦片，生成了 512×320、190,055 字节 PNG，实际查看确认地图、圆圈和中心正确。此图片只用于验证截图生成，没有创建、删除或修改真实手表区域；平台对实际区域保存的最终结果需由所选区域的保存操作确认。
