# 新版主页设计说明

JZClientForNode 主页以当前手表的位置为中心。桌面第一行左侧放“我的手表”和地图，右侧放运行状态；设备资料从手表名称旁的信息按钮打开弹窗查看。第二行放常用功能与公告。宽度至少 1000px 的横屏将面板运行环境放在右侧运行状态下面，竖屏或更窄的窗口仍将环境放在底部，手机先显示手表与地图。MD3 风格由现有 React 组件实现；配色、原字体、基础控件与导航已成为全站公共设计，主页保留自己的内容排布。

## 页面结构

| 区域 | 显示内容 | 设计目的 |
| --- | --- | --- |
| 顶部与导航 | JZClientForNode 品牌、固定顶栏、浅深切换、账号入口、圆角矩形主导航与独立插件入口 | 滚动时仍能操作账号与导航 |
| 标题旁的一言 | 小字原文、来源、换一句 | 放在标题右侧，保持轻量 |
| 手表名称旁的信息按钮 | 小圆形图标按钮，主卡片及更多列表均提供 | 查看指定手表的资料，不改变当前选择 |
| 手表设备信息弹窗 | watchId、IMEI、号码、固件、绑定关系、电量来源与时间、最近通知与推送位置、设备详情入口 | 按需查阅资料，减少主页常驻内容 |
| 标题栏右侧胶囊 | 家长账号、消息连接、OneBot；左侧功能图标，右侧绿勾或红叉 | 紧凑显示连接结果，可进入对应管理页 |
| 第一行左侧我的手表 | 两张设备选择卡、名称旁信息按钮、型号右侧状态角标、卡片右侧电量环、更多设备浮层 | 识别当前设备并切换，省去重复概览 |
| 第一行左侧定位地图 | 扩大的地图、最近上报坐标、地址、时间、精度、打开定位页 | 让位置成为主页主要内容，并衔接完整定位功能 |
| 第一行右侧运行状态 | 运行时长、CPU 与系统内存实时折线、当前使用率、程序内存 | 便于同时查看设备和服务状态，呈现实际采样变化 |
| 第二行常用功能 | 安全区域、全部功能、插件、账号与集成 | 插件快捷入口直达独立管理页，其余功能保留原入口 |
| 第二行最近公告 | 最近两条公告、置顶标记、日期和摘要 | 提供可扫描的信息与完整公告入口 |
| 面板运行环境 | 系统架构、Node.js、处理器、主机名；横屏右侧、竖屏与窄屏底部 | 以四个默认字段简洁展示主机环境，其余信息在向下浮层查看 |
| 页脚 | 原有 Node.js 吉祥物与 `powered by laolibuhuifei` | 居中保留作者署名与原链接 |

桌面采用左侧导航，导航项为 16px 圆角矩形。顶栏在滚动时固定于顶部，页面标题、一言、刷新按钮和三个连接胶囊排列在同一区域，胶囊在最右侧右对齐。胶囊不显示已登录、已连接、运行中等状态文字，具体状态由悬停提示和读屏说明提供。正文第一行左侧放“我的手表”和地图，右侧放运行状态；第二行并排放常用功能与公告。宽度至少 1000px 且为横屏时，运行环境排列在右侧运行状态下方，两张卡片均撑高，与中间 20px 间隔合计，与左侧“我的手表”卡片总高度齐平；竖屏或宽度不足 1000px 时仍将环境放在页面底部。运行环境始终使用同一份 DOM，由响应式布局调整位置。

“进程与账号详情”改为按钮下方的非模态 Popover，展示内核、CPU 核心、负载、进程与账号字段。浮层进入浏览器顶层，不参与环境卡片尺寸计算，展开后仍保持右侧两卡与左侧手表卡片等高。高度限制在可用视口内，内容可滚动；下方空间不足时将触发按钮滚动到更合适的位置，接近页面末尾时按需增加临时留白，关闭或卸载后清理。Escape 和关闭按钮返回触发控件焦点，点击外部关闭浮层。

地图上方原有的设备设置、聊天和详情三按钮组已删除。设备详情入口保留在手表资料弹窗中；聊天、定位和其他管理功能继续通过主导航、地图入口与常用功能进入。

手机采用单列，三个连接胶囊在标题区另起一行，保留左右图标；文字与状态图标使用固定小间距，避免自动外边距在竖屏撑出大片空白。优先显示“我的手表”与地图，随后排列运行状态、常用功能和公告，运行环境放在底部。设备资料按需弹出。底部导航保留主页、聊天、定位、功能和“更多”五个位置，适配安全区域。“更多”向上打开浮层，显示“我的”、“插件”管理和全部可用应用；标题固定，仅入口列表滚动，高度限制在顶栏与底部导航之间，支持 Escape、外部关闭与选择后焦点返回。当前选中“我的”、插件管理或插件应用时，“更多”处于选中状态。一言以小字留在标题右侧，来源在窄屏收起。

桌面与平板侧栏保留独立的“插件”管理项，并在基础导航后完整追加可用插件应用，支持纵向滚动，不只展示前四个。应用入口要求插件总开关开启，并且插件有 UI、已加载、未禁用。主页“插件”快捷入口直接进入管理页；“我的”插件板块仍展示全部可用应用并保留管理按钮，应用也可以从导航直接访问。

设备选择默认显示两张卡片，各自包含名称、名称右侧的小圆信息按钮、型号、型号右侧的圆角矩形状态角标，以及右对齐的电量环。“当前手表”及重复的名称、型号和状态概览已移除。名称超过五个字符时截取前五个并加 `...`，宽度更窄时再由 CSS 省略，完整名称保留为可访问名称和悬停提示。设备选择按钮与信息按钮为独立控件；点击信息按钮不会切换选中的手表或更新地图。

只有一台手表时，主页选择卡最大宽 320px 并靠右排列，保留设备卡比例。

当每张主卡片自身宽度不超过 170px 时，该卡片使用 84px 高的扁卡片排布，隐藏电量圆环，在右上角显示电量数字，同时使用沿卡片圆角描边的进度线表达剩余电量。描边起点为左上角，电量降低时从该起点沿顺时针方向逐段消失。此规则由具名容器 `home-watch-choice` 按卡片自身宽度判断，保证卡片在狭窄区域也能为名称、信息按钮和型号留出空间；可用宽度充足的主卡片与更多列表继续显示圆环，只有一台手表时不会因整组容器较窄而提前隐藏圆环。

“手表设备信息”弹窗使用点击设备的 `watchId` 匹配资料，主卡片和更多列表均可打开。弹窗保留设备标识与补充诊断信息，点击“设备详情”才会选择被查看的手表并进入其概览页。弹窗支持焦点约束、Escape 和关闭按钮，关闭后返回触发控件；账号失效后关闭资料弹窗并隐藏缓存设备信息。

设备超过两台时，前两张卡片同时缩短，最右侧出现竖向圆角按钮，显示向下箭头和剩余数量。点击后向下打开可滚动的原生 Popover；支持 Escape、点击外部关闭，选择后关闭并返回按钮焦点。选中的额外设备替换第二张主卡片，被替换的设备仍留在更多列表。手机浮层为底部导航留出高度。按钮不使用三个点，省略号只用于过长名称。

其他需要选择手表的业务页使用同一个 `HomeWatchPicker` 的标题版本，由 `DeviceWatchPicker` 放在 `PageHeader` 标题右侧。默认两张卡高 64px，超过两台时显示向下浮层，额外选中设备回显到第二张卡；单台固定桌面 165px、手机 150px 宽，不横向拉长。标题保持一行，说明与操作放在下一行。手机卡片名称省略，信息按钮移到右下角并保留 44px，状态角标与电量数字分开排列。资料弹窗与主页共享，`0%` 和未知值继续区别显示；查看信息不切换设备。浮层下方空间不足时按需添加页面末尾留白，关闭或卸载后清理。

## 视觉与组件

字体继续使用 `JZCatBook`（「送给猫咪的一本书」）。正文基准 17px，操作文字 16–18px，辅助标签以 14–15px 为主，页面标题最高 34px。设备电量、ID 和运行数值使用等宽数字排版；长 ID、IMEI 和主机信息允许换行。

浅色模式的画布为 `#f5f5fa`，白色卡片承载信息，主色为 `#515d98`；深色模式对应 `#171820` 画布、`#22232e` 卡片和 `#bac3ff` 主色。选中状态使用浅色容器与勾选标记，成功和警告各有文字与状态色。

默认深色，只保留浅色与深色切换。原来保存的浅色选择继续生效；无保存值或保存值为旧 `auto`、`system` 时使用深色。太阳或月亮图标表示下一次切换目标，点击保存选择；访问验证页遵循相同规则，主题不再跟随系统自动变化。

常规电量使用原生 SVG 圆环，百分比位于中心，圆弧由实际电量计算；窄容器主卡片使用数字和圆角边框进度线。两种形式中，`0%` 均显示零值且没有已填充进度，未知值显示 `—`，不会伪装成零电量；不超过 20% 使用警告色。地图复用现有 `TileMap`，保留缩放和位置展示能力。地图高度在宽桌面为 480px、中等桌面和平板为 400px、手机为 320px，加载占位和空态使用相同高度；标题区保留位置刷新图标与完整定位入口。

复用项目的 `PageHeader`、`Card`、`Button`、`Badge`、`Modal`、`EmptyState`、`ErrorState` 和 `Skeleton`。设备资料通过共享 `Modal` 展示，进程详情通过 `AnchoredPopover` 展示，更多手表使用浏览器原生 Popover。小圆信息按钮提供完整设备名称对应的可访问标签，并保留合适的操作区域；键盘操作显示焦点。静态骨架屏对应页面结构，避免空白加载。配色角色定义在 `material-theme.css` 的根元素，挂载到 `body` 的资料弹窗也继承正确浅深主题。

运行状态中的系统 CPU 与系统内存折线由 `HomeRuntimeTrends.tsx` 及配套 CSS 绘制，使用原生 SVG 和主页现有颜色。图表初始只显示当前数值与“采集中”，随着真实采样增加再形成折线，不绘制孤立点或末端圆点，不填充虚构的历史记录。

每次成功刷新时，曲线用约 420ms 连续过渡到新位置，当前数值立即更新。正在移动时收到新采样会从当前可见位置继续，不会先跳到上一轮终点。图表离开视口、页面隐藏或启用“减少动态效果”时停止过渡并显示最终位置。未登录或登录失效时，连接入口使用账号轮廓图标。

页面切换使用 180ms 淡入与纵向小幅位移，切换手表只对设备内容使用 180ms 淡入与横向小幅位移。当前页面与设备的身份保持稳定，轮询和普通刷新不会重播这些动画。按压设备卡有轻微缩放反馈；`prefers-reduced-motion` 开启时停用位移、缩放与切换动画。

主导航和共享 Tabs 的选中背景使用 200ms 滑动指示层，缓动为 `cubic-bezier(0.22, 1, 0.36, 1)`。手机移动图标背景，桌面移动导航按钮背景；快速切换从当前可见位置接续。首次显示和布局变化直接定位，选中项自动进入滚动区域的可见范围；页面隐藏、指示层离屏或减少动态效果时停止动画。Tabs 的方向键、Home、End 和跳过禁用项逻辑保留。

已安装 [ibelick/ui-skills](https://github.com/ibelick/ui-skills)，本版采用其中的 `baseline-ui` 与 `fixing-accessibility` 约束间距、字号、现有组件复用、可访问名称和错误提示。

## 功能与数据逻辑

| 操作 | 行为 |
| --- | --- |
| 切换手表 | 更新全局 `watchId`，替换当前设备与地图；刷新数据后保留当前选择 |
| 更多手表 | 展开剩余设备的可滚动浮层；选择后回显到第二张主卡片，并保持当前选择 |
| 查看手表设备信息 | 点击名称旁信息按钮，用该手表 ID 打开资料弹窗，不改变当前选择 |
| 设备详情 | 从资料弹窗选择被查看的设备 ID，再进入 `overview` |
| 安全区域 | 从第二行常用功能使用当前设备 ID 进入 `guard`；新增危险区域时搜索地点或地图选中心，再设置半径 |
| 打开定位页 | 从地图区携带当前设备 ID 进入 `location` |
| 刷新手表位置 | 重新读取当前设备最近上报的位置；读取期间禁用刷新图标，失败时保留已有位置 |
| 主导航聊天 / 消息连接 | 进入 `chat` 会话列表，由用户选择收件人，不按手表名称推测会话 |
| 绑定手表 | 已登录进入 `bind`；未登录或登录过期进入 `account` |
| 全部功能 / 插件 / 账号与集成 | 分别进入 `more`、独立 `plugins` 管理页和 `me`；“我的”插件板块仍保留应用及管理入口 |
| 查看公告 | 进入公告列表，单条公告携带对应 `id` |
| 设备补充资料 | 在资料弹窗查看绑定关系、电量来源和时间；有记录时显示最近通知与推送位置 |
| 进程与账号详情 | 在按钮下方打开可滚动浮层，展示内核、核心数、运行时长、负载、PID、进程 CPU、内存与有效登录账号字段，卡片大小不变 |
| 实时日志 | 从运行环境进入 `logs` |

主页通过 `/api/system` 获取设备、账号及运行信息，每三秒轮询。系统接口中的设备摘要按 `watchId` 与全局完整手表数据合并，摘要覆盖同名字段，完整数据补充 IMEI、号码、固件、绑定关系及推送记录。手动刷新同时更新主页数据、公告和全局手表列表。

系统 CPU 与系统内存趋势复用主页系统接口的成功响应，分别采集 `system.cpuPercent` 与 `system.memPercent`。最近两分钟内最多保留 41 个真实采样点，初始只有当前成功响应对应的点，并标记“正在采集趋势”。缺失或无效的数值使对应曲线断开，不能补为 `0`；实际零值仍是有效采样。接口失败时保留之前的采样，不追加点；组件记住中断，在恢复后的第一个成功点前断开线段，即使只失败了一次轮询也不连线。手表切换不会重置主机趋势，检测到后端进程 PID 改变或运行时长回退时清空已有采样并重新采集。

接口暂时失败时保留已有数据并显示重连提示；首次加载失败显示重试入口。电量 `0%` 是有效值，缺失值显示 `—`，未知在线状态显示“状态未知”。最近收到通知标注为接收时间，不据此判断在线；最近推送位置仅在有记录时展示，并附带时间。

地图读取当前设备的 `/api/watch/{watchId}/location`，展示最近上报位置、地址、时间和可用精度。切换设备时先清除上一台设备的地图数据，再读取新设备位置；没有坐标时显示明确的空状态。已加载的位置刷新失败时保留内容并提示重试。地图显示的是最近上报记录，其状态与时间一同呈现。

登录状态同时检查账号标记与 `tokenInvalid`。即使接口仍返回缓存手表，登录过期后也隐藏这些设备，关闭已打开的设备资料弹窗，并引导重新登录。进程详情的当前账号显示为未登录，`mobileId` 显示 `—`，不展示缓存身份。已登录但未绑定手表时引导添加第一台设备。

公告通过 `/api/announcements` 加载，主动重试使用 `?refresh=1`。失败提示显示在公告区域，已有公告可继续阅读。

每日一言通过 `/api/yiyan` 加载。“换一句”请求 `?refresh=1`，请求期间禁用按钮并保留原文；失败后保留原文和错误提示，重试成功才替换。普通刷新恢复缓存请求。

页脚作者链接保持为 [laolibuhuifei](https://github.com/laolibuhuifei)，署名前使用项目原有 `/assets/node-mascot.svg` 吉祥物。

危险区域新增默认半径 300 米，搜索结果和地图选择共享同一中心。经纬度以只读信息展示，不要求用户手工输入；原新增接口只接收 `latitude`、`longitude`、`radius`，地点名称与地址用于确认而不保存。常见区域保持只读，危险区域删除继续使用原接口。搜索来源、取消与错误处理、开发服务和坐标验证范围见 [地点搜索与地图选择](../../docs/安全区域/地点搜索与地图选择.md)。
