# 聊天：手机布局与消息状态

聊天页沿用原字体 `JZCatBook` 与全站 MD3 颜色、卡片和按钮。手机会话列表、消息阅读和输入区各自占据明确空间，IM 连接状态放在“聊天”标题下方的小角标中，列表标题与搜索同行。位置弹窗改用共享地点搜索和地图选择；原会话、消息和媒体接口继续使用，发送目标仍由会话身份确定。

## 页面如何排列

| 场景 | 排列方式 | 主要操作 |
| --- | --- | --- |
| 桌面 | 左侧会话列表，右侧消息区与输入区 | 搜索与切换会话、阅读和发送 |
| 手机未选会话 | 显示完整会话列表，工作区内部滚动 | 点击手表单聊或家庭群 |
| 手机已选会话 | 全屏会话标题、消息区、输入区纵向排列，暂时隐藏全局外壳 | 返回会话列表、阅读与发送 |
| 页面标题 | 标题下显示 IM 小角标，标题操作区保留重连与刷新 | 识别连接状态、主动重连 |

手机会话卡至少高 88px，头像为 48px，卡片之间保留 10px 间距。长名称在可用空间内省略，完整名称保留给悬停与可访问名称；副标题区分单聊与家庭群，消息数量单独显示。列表滚动保持在工作区内部，不把整页不断撑长。

手机“全部会话”与数量在左，搜索框在同一行右侧。搜索框视觉高度为 38px，最大宽 210px，输入文字约 14px；窄屏使用可用剩余空间，列表滚动仍独立于搜索区。

进入手机会话后，聊天页铺满当前可视视口，隐藏全局顶栏、底部导航、页面标题、设备选择和页脚。消息在自己的容器滚动，输入区贴在视口底部并保留系统安全区域；返回恢复原列表与外壳。会话使用普通 section，不是聊天 Dialog；可视视口变化时更新高度和顶部偏移，空间很小时压缩标题与输入区留白。详见 [手机全屏与发送修复](../../docs/聊天/手机全屏与发送修复.md)。

页面标题右侧的设备选择使用全站两张 64px 小卡规则。它选择当前设备管理对象，聊天收件人仍由所选会话确定，不能根据手表昵称推测发送目标。

## 头像如何找到正确设备

宝贝资料和已知设备的聊天头像复用 `GET /api/watch/{watchId}/avatar`，读取响应中的 `url`；会话自带有效头像地址时也可直接使用。图片只在有有效来源时显示，读取失败或来源缺失时使用人物图标，家庭群使用群组图标。

聊天优先使用 `/api/chats` 目标的可选 `watchId`。后端用 `watchPeerOf` 只匹配单聊中 `accountType=1` 且 `imAccountId` 等于 `receiverId` 的手表成员，再用 `watchIdOf` 将该成员的有效 `accountId` 作为设备 ID；不使用昵称或当前全局选中的手表推测。

真实 `/dialogaccount/merge/accounts` 成员含 `accountId` 和 `customIcon`，没有原头像读取所需的 `icon`、`bindNumber`；手表资料含 `icon`，却没有前端旧映射所需的 `imAccountId`。只从成员签头像或只依靠资料 IM ID 都无法覆盖该结构。只读核对已确认这两台手表的成员 `accountId` 等于资料 `id` 和绑定关系 `watchId`。

| 标识或来源 | 在当前流程中的用途 |
| --- | --- |
| `peer.imAccountId` 与 `receiverId` | 精确找出这条单聊的手表成员 |
| `peer.accountId` | 作为该设备的 `watchId`，随会话目标返回 |
| 手表资料 `icon` | 使用原头像下载/签名流程取得图片地址 |
| 旧成员 `icon` 或 `bindNumber` | 资料头像不可得时沿原逻辑回退 |

没有设备 ID 时，前端可用会话 key 调用 `GET /api/chats/avatar?key=…`。该接口仍先根据单聊成员的 `accountId` 读取手表资料，并用原 `getAvatarUrl(watchId, account)` 签头像；没有有效资料地址时，再尝试旧成员头像来源。非单聊、成员缺失或没有可用头像时返回空地址。

前端保留 `profile.account.imAccountId` 映射，兼容带有该字段的旧资料；当前服务提供显式 `watchId`，头像不再要求资料必须包含 IM ID。IM ID 标识会话、accountId/watchId 标识设备，不能互换。会话自带的有效图片地址仍优先使用。

身份匹配只依赖 ID。同名手表不会互相借用头像。请求支持 AbortController 取消，以 `watch:{id}` 或 `chat:{key}` 隔离结果；切换会话、设备列表变化或登录失效后，迟到响应不覆盖当前身份。

## IM 状态是什么意思

| 读数 | 标题显示 | 含义 |
| --- | --- | --- |
| 尚未获得 IM 状态 | `IM 状态获取中` | 仍在读取连接结果 |
| 未建立连接 | `IM 未连接` | 可使用标题旁的重连操作 |
| 已连接但连接存活检查未通过 | `IM 正在重连` | 服务正在恢复连接 |
| 已连接且存活 | `IM 已连接` | 消息服务连接可用 |

状态位于“聊天”标题下方，使用约 11px 文字、13px 图标和 6px 圆角，避免和右侧操作争抢空间。已连接使用绿色语义容器和圆形勾，其余状态使用明确文字及圆形叉，辅助说明保留在提示中；状态变化可被读屏感知。

IM 状态描述消息服务，不等于手表设备的在线状态。底部原连接板块移除；桌面与列表状态在页面标题下，手机全屏会话中移到孩子名称下方，避免外壳隐藏后丢失连接读数。主动重连图标保留在普通页面标题操作区。连接异常或长时间未收到数据时，消息区仍可显示诊断提示和重连操作。

## 位置消息如何发送

位置弹窗复用 `GuardPlacePicker` 的 `purpose="message"` 模式。可以按城市、学校或地点关键词搜索 POI，点击搜索结果、直接点地图，或拖动后选择“使用地图中心”；地图聚焦后的 Enter 同样能选中心。初始没有选中地点，查看地图不等于已选择。

界面显示“选择发送位置”，选中后回显名称、地址和只读坐标。它使用经过鉴权的 `/api/map/search` 与既有 GCJ-02 地图坐标流；此模式不显示安全区域半径。地图也可在普通与卫星图层间切换，中心与选点保持。

搜索和选点只更新本地表单。只有点击“发送位置”才调用原消息发送方法：

```ts
onSend('location', {
  latitude: place.latitude,
  longitude: place.longitude,
  poi: place.address ? `${place.name} · ${place.address}` : place.name
})
```

没有选点时不能发送；取消只关闭弹窗。发送期间禁用选点、取消和发送，避免重复提交；失败保留选点，成功后才关闭。地图直接选点的名称为“地图选定位置”，POI 名称和地址沿原 `poi` 字段提交，不新增消息类型。公开搜索、坐标转换与硬件验证边界见 [地点搜索与地图选择](../../docs/安全区域/地点搜索与地图选择.md)。

## 保留的交互与数据规则

每个会话继续独立保存未发送草稿。Enter 发送，Shift + Enter 换行，中文输入法确认候选不会误发送。切换会话取消旧消息请求，消息 key 与媒体节点保持稳定，轮询不重建正在播放的音视频。

文字、表情、颜文字、位置、链接、图片、视频、录音和媒体外链仍使用原功能。发送期间防止重复提交，失败保留内容；录音先试听再发送，关闭后释放录音资源。未登录、登录失效、无会话、搜索无匹配和消息读取失败都有原有的明确状态。
